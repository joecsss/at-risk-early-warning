# ระบบเตือนภัยล่วงหน้าสำหรับนักศึกษาที่เสี่ยงด้านผลการเรียน (Explainable ML)

โปรเจกต์ปริญญานิพนธ์ — ทำนายนักศึกษากลุ่มเสี่ยงด้วย Machine Learning ที่ "อธิบายได้" (SHAP)
พร้อมแดชบอร์ดสำหรับอาจารย์ที่ปรึกษา

## เทคโนโลยี
Python · pandas · scikit-learn · imbalanced-learn · SHAP · Streamlit

## เริ่มต้น (Setup)
```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

## รันตามลำดับ
```bash
python src/data_prep.py        # เตรียมข้อมูล -> data/processed_*.csv + metadata.json
python src/train.py            # เทรน+ประเมิน -> models/model.joblib + metrics.json
python src/explain.py          # (ไม่บังคับ) พิมพ์ตัวอย่างเหตุผล + เซฟกราฟ SHAP ลง reports/
streamlit run src/app.py       # เปิดแดชบอร์ด -> http://localhost:8501
```

รันใหม่ทั้งชุดหลังแก้โค้ดหรือเปลี่ยนข้อมูล:
```bash
python src/refresh.py          # data_prep -> train -> explain -> make_report ตามลำดับ
```

### ตัวเลือกที่ใช้บ่อย
```bash
python src/data_prep.py --feature-set early   # ใช้เฉพาะข้อมูลแรกเข้า + ภาค 1 (เตือนได้เร็วกว่า)
python src/data_prep.py --refresh             # ดาวน์โหลดข้อมูลดิบใหม่ (ปกติใช้แคช)
python src/train.py --target-recall 0.90      # ตั้งเป้า recall ของกลุ่มเสี่ยง
python src/train.py --operating-point f2      # เลือกจุดทำงานที่ F2 สูงสุดแทน
```

## ผลลัพธ์ปัจจุบัน (เฟส 1)

ชุดข้อมูล UCI id=697 · 4,424 คน · กลุ่มเสี่ยง (Dropout) 32.1% · แบ่ง train/test 80/20

เปรียบเทียบด้วย **5-fold cross-validation บนชุด train** (ชุด test เก็บไว้วัดครั้งเดียวตอนท้าย)

| โมเดล | PR-AUC | ROC-AUC | Recall@0.5 | Precision@0.5 |
|---|---|---|---|---|
| **logreg** (one-hot + scaling, class_weight) | **0.883** | 0.921 | 0.813 | 0.765 |
| rf (class_weight balanced_subsample) | 0.875 | 0.920 | 0.749 | 0.832 |
| gb (baseline ไม่จัดการ imbalance) | 0.880 | 0.920 | 0.747 | 0.852 |
| hgb_balanced | 0.870 | 0.918 | 0.799 | 0.782 |
| gb_smote (SMOTE ภายใน fold) | 0.879 | 0.920 | 0.785 | 0.802 |

ผลของโมเดลที่เลือก (logreg) บน **ชุดทดสอบ**:

| จุดทำงาน | Recall | Precision | F1 | F2 | PR-AUC | พลาดกลุ่มเสี่ยง (FN) |
|---|---|---|---|---|---|---|
| threshold 0.50 | 0.852 | 0.793 | 0.822 | 0.840 | 0.901 | 42 / 284 |
| threshold 0.42 (จูนให้ recall ≥ 0.85) | 0.863 | 0.742 | 0.798 | 0.836 | 0.901 | 39 / 284 |

**เตือนได้เร็วแค่ไหน?** ถ้าใช้เฉพาะข้อมูลที่รู้ตั้งแต่จบภาคเรียนแรก (`--feature-set early`,
37 ฟีเจอร์) ผลลดลงไม่มาก — PR-AUC 0.876, recall 0.863 ที่ precision 0.677 บนชุดทดสอบ
แปลว่าระบบเตือนตั้งแต่สิ้นภาค 1 ได้โดยแลกความแม่นยำเพียงเล็กน้อย

### หมายเหตุเชิงระเบียบวิธี
- **ไม่เลือกโมเดลด้วย recall ดิบ** เพราะโมเดลที่ทายว่า "เสี่ยงทุกคน" จะได้ recall = 1.0
  → เลือกด้วย PR-AUC จาก CV แล้วค่อยจูน threshold ให้ได้ recall ตามเป้า (ค่าเริ่มต้น 0.85)
- ข้อมูลไม่สมดุล จึงรายงาน PR-AUC / F2 แทน accuracy
- SMOTE ทำงานภายใน fold ของ cross-validation เท่านั้น จึงไม่เกิดการรั่วของข้อมูล (data leakage)

## แดชบอร์ด (Streamlit)
- **แท็บ 1 รายชื่อกลุ่มเสี่ยง** — เรียงตามความเสี่ยง, แถบสีระดับความเสี่ยง, ฟิลเตอร์ตามสาขา/ระดับ,
  ค้นหารหัสนักศึกษา, ดาวน์โหลด CSV
- **แท็บ 2 อธิบายรายบุคคล** — ค่าความเสี่ยง, กราฟ SHAP รายคน (แดง = ดันความเสี่ยงขึ้น /
  เขียว = ดึงลง), ค่าจริงของนักศึกษาในแต่ละปัจจัย, และ **ข้อเสนอแนะการช่วยเหลือ** ตามปัจจัยที่พบ
- **แท็บ 3 ภาพรวมโมเดล** — ปัจจัยสำคัญระดับภาพรวม, การกระจายความเสี่ยง,
  ตารางเทียบโมเดล, confusion matrix ที่เกณฑ์ปัจจุบัน
- ปรับ threshold ได้จากแถบข้างซ้าย (เห็นผลต่อ recall/precision ทันที) และอัปโหลด CSV ของรุ่นใหม่ได้

## แผนพัฒนา (Roadmap)
- **เฟส 1 (ภาคต้น / เค้าโครง–Progress):** เตรียมข้อมูล + โมเดล baseline + ประเมิน (เน้น Recall) + SHAP + แดชบอร์ดเบื้องต้น ✅ **เสร็จแล้ว**
  - ✅ feature engineering (สัดส่วนวิชาที่ผ่าน, ความเสี่ยงการเงิน, ช่องว่างผลการเรียน ฯลฯ)
  - ✅ เทียบ 5 โมเดลด้วย cross-validation + จัดการ imbalance (class_weight / SMOTE)
  - ✅ จูน threshold ตามเป้า recall แทนการเลือกโมเดลด้วย recall ดิบ
  - ✅ SHAP ที่ถูกต้อง (background จากชุด train + รวมค่าของ one-hot กลับเป็นฟีเจอร์ต้นฉบับ)
  - ✅ แดชบอร์ด 3 แท็บ พร้อมฟิลเตอร์/ค้นหา/ข้อเสนอแนะ/ดาวน์โหลด
- **เฟส 2:** จูนไฮเปอร์พารามิเตอร์ (GridSearch/Optuna), ทำนายเชิงเวลา (เตือนตั้งแต่สัปดาห์ที่ 2–4 ด้วย OULAD),
  บันทึกประวัติการช่วยเหลือ, ระบบผู้ใช้/สิทธิ์การเข้าถึง
- **เฟส 3:** (ถ้าเป็นไปได้) ทดลองกับข้อมูลบริบทไทย/มข. โดยคำนึงถึงความเป็นส่วนตัว

## หมายเหตุ
- repo นี้เก็บเฉพาะโค้ด — ตัวเล่มปริญญานิพนธ์ (LaTeX) ไม่ได้เผยแพร่ที่นี่
- เริ่มด้วยชุดข้อมูลสาธารณะ (UCI dropout) เพื่อไม่ให้ติดเรื่องขอข้อมูล
- ระบบเป็นเครื่องมือ "สนับสนุนการตัดสินใจ" ของอาจารย์ ไม่ตัดสินผลการเรียนอัตโนมัติ
- รหัสนักศึกษาในแดชบอร์ด (`S0001`…) เป็นรหัสจำลอง เพราะชุดข้อมูล UCI ไม่มีตัวระบุตัวตน
- ค่า SHAP รายงานในหน่วย log-odds (บวก = ดันความเสี่ยงขึ้น, ลบ = ดึงลง)
